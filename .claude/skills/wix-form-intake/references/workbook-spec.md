# 面談準備ワークブックの構成

アポイントメントのあるクライアントについて、面談の前に作る .xlsx。
目的は2つ: (1) 面談で聞くことを漏れなく並べたヒアリングメモ、(2) 論点の基本知識を事前に整理した解説。
面談中はこのファイルを開いて黄色の欄に回答を書き込みながら進める想定。

- 言語: 英日併記（クライアントの多くが外国籍のため）。日本語のみのクライアントなら日本語だけでよい。
- 生成: 内容を JSON にまとめて `scripts/build_workbook.py` を実行する（JSON 形式はスクリプト冒頭）。
- ファイル名: `<姓 or 法人名>_Prep_Workbook_<面談日 YYYYMMDD>.xlsx`
- 保存先: `<クライアントフォルダ>/Workbook`

## 材料を集める

1. フォームの回答（基本情報）: 居住者区分、来日日、国籍、職業・事業、所得の種類、海外住所・納税者番号の有無など。
2. 問合せメール・これまでのやり取り（Gmail で回答者のアドレスを検索）: 相談の目的、困っていること、期限。
3. 予約内容: 日時、形式、選んだサービス、予約時の質問への回答。
4. クライアントフォルダ: `Documents_` に既に届いている書類、過去の面談メモ（`…_Meeting_Memo…`）、報告書。
5. 参照スキル（数字・期限・報酬は必ずここから。記憶で書かない）:
   - `tokyo-advisory-services`: 業務範囲、報酬の目安、必要資料、期間、年間スケジュール
   - `us-estate-trust-tax`: 米国の信託・遺産（Form 1041、DNI 等）
   - 日本の税法（居住者区分、国外財産調書、相続税の納税義務者等）は条文・国税庁の情報に基づいて書き、
     自信が無い点は「要確認」と書く。

## シート構成

### 1_Overview（概要）

列: `Item / 項目`（28）、`Detail / 内容`（80）

行の例:
- Client / 顧客（氏名・法人名、区分フォルダ）
- Meeting / 面談（日時 JST、形式、Zoom リンクの有無、出席者）
- Service booked / 予約サービス
- Purpose / 相談の目的（問合せから1〜3行で要約）
- Key facts from the form / 基本情報の要点（居住者区分の手がかり、来日日、所得の種類など。番号類は書かない）
- Documents already received / 受領済み資料（`Documents_` のファイル名を要約）
- Issues to cover / 論点（ヒアリングと解説のシートで扱う論点の一覧）
- Goal of the meeting / 面談のゴール（例: 申告の要否の判断、見積りの提示、必要資料の確定）
- Next steps after meeting / 面談後の流れ（`meeting-follow-up` スキルで面談フォローを作る、など）

### 2_Hearing（ヒアリングメモ）

列: `#`（5）、`Topic / 論点`（18）、`Question (EN)`（45）、`質問（日本語）`（40）、
`Why we ask / 確認の理由`（35）、`Answer / 回答`（45、input）、`Follow-up / 追加確認・資料`（30、input）

- `input_columns`: Answer と Follow-up の列（0始まりで 5, 6）。`group_column`: Topic の列（1）。
- 論点ごとにまとめ、面談で聞く順に並べる。全体で 15〜30 問程度。
- フォームで既に分かっていることは聞き直さず、「確認」として短く書く（例「来日日 2024/4 で相違ないか」）。
- 必ず入れる論点（該当するもの）:
  - 居住者区分・滞在履歴（来日日、出国予定、日本での住所、家族の所在、永住者／非永住者）
  - 所得の全体像（給与・事業・不動産・配当・譲渡・年金、国内外の別、源泉徴収の有無）
  - 国外資産（金融口座、不動産、株式・RSU、暗号資産、国外財産調書の要否の目安）
  - 他国での申告状況（米国市民・グリーンカード保有者なら米国申告、FBAR、二重課税の調整）
  - 家族（配偶者・扶養親族の所得と所在、扶養控除・配偶者控除の可否）
  - 期限と過去分（未申告年度、税務署からの通知、期限後申告の有無）
  - 法人の場合: 設立日、事業年度、資本金、株主構成、役員、従業員、給与計算・社会保険、
    消費税（インボイス登録）、会計ソフト、記帳の担当、銀行口座、前任の税理士
  - 相続の場合: 被相続人の死亡日・国籍・住所、相続人、遺言、財産の所在国、評価に必要な資料、期限（10か月）
- `Why we ask` には、その回答で何が決まるか（申告の要否、適用される制度、報酬の区分など）を1行で書く。

### 3_Basics（基本知識の解説）

列: `Topic / 論点`（20）、`Explanation (EN)`（60）、`解説（日本語）`（60）、
`Key thresholds & dates / 基準・期限`（35）、`Source / 出典`（25）

- 2_Hearing の各論点について、面談で説明できるように基本の仕組みを書く。1論点 3〜6 文。
- クライアントに説明する立場で、平易に書く（条文番号は Source 列へ）。
- 金額基準・期限・税率は Key thresholds 列に分けて書き、出典（法令名、国税庁タックスアンサー番号、IRS の Form/Publication、
  参照スキル名）を Source 列に書く。確かでない数字は書かずに「要確認」とする。
- 例: 居住者・非永住者・非居住者の区分と課税範囲／確定申告が必要な場合と期限（3/15）／国外財産調書（5,000万円超）／
  外国税額控除／米国市民の申告義務と FBAR／扶養控除の要件（国外居住親族の書類）／法人の設立届と青色申告承認申請の期限／
  消費税の納税義務とインボイス／相続税の納税義務者の区分 など、案件に関係するものだけ。

### 4_Documents（必要資料）

列: `Document / 資料`（35）、`Purpose / 用途`（40）、`Status / 状況`（15）、`Notes / 備考`（35、input）

- `tokyo-advisory-services` の必要資料リストから、この案件に必要なものを選ぶ。
- Status は `受領済`（`Documents_` にあるもの）／`依頼予定`／`該当すれば` のいずれか。

### 5_Glossary（用語集）

列: `Term (EN)`（28）、`用語（日本語）`（22）、`Meaning / 意味`（70）

- 面談で出てくる用語を 10〜20 語。英日の対訳と1行の意味。

## 仕上げの確認

- 作った .xlsx を openpyxl で読み直し、シート数・行数・空欄が意図どおりかを確かめる。
- マイナンバー・SSN・口座番号・パスポート番号はワークブックに書かない（必要なら「フォーム回答あり」とだけ書く）。
- 報告では、扱った論点の一覧とヒアリング項目の数を示す。
