# クライアントへ伝えたタイムライン → Wix カレンダー

成約済みのクライアントにメールや Slack で伝えたスケジュールを、Wix の **カレンダーの予定**（Calendar Events API）として
山本真美子のスケジュールに登録する。予約（Booking）は作らないので、クライアントには Wix から通知は届かない。

サイト ID・スケジュール ID・API は `references/config.md` に記載。
Wix のツールを使う前に `WixREADME` を1回呼ぶ（Wix MCP の決まり）。

## 手順

### 1. タイムラインを伝えたメッセージを特定する

- ユーザーがクライアント名・件名・チャンネルを指定したらそれを使う。
- **Gmail:** `search_threads` で送信済みメールを探す。例: `from:me to:<クライアントのアドレス> newer_than:30d`、
  キーワードは `スケジュール OR タイムライン OR 期限 OR schedule OR timeline OR deadline`。
  見つけたら `get_thread` で開き、**こちら（東京アドバイザリー）が送った本文**を読む。
  引用部分（`>` で始まる行、「〜 wrote:」以下）の古い日程は使わない。
- **Slack:** `slack_search_public_and_private` でクライアントのチャンネル・DM を探し、`slack_read_channel` /
  `slack_read_thread` で読む。日程を伝えた投稿がこちらの投稿であることを確かめる。
- 同じクライアントに日程を何度か送っている場合は **最新のもの** を正とし、古いものと食い違う日程は計画表の備考に書く。
- 見つからない、または候補が複数ある場合は推測せずユーザーに確認する。

### 2. 予定を抜き出す

メッセージから「日付・（あれば）時刻・内容」を1件ずつ抜き出す。次のように扱う。

| 書き方の例 | 登録の仕方 |
|---|---|
| 「11/1(土) 14:00〜15:00 申告書レビュー」 | 時刻ありの予定。14:00〜15:00 |
| 「11/5 10:00 Zoom 面談」（終了時刻なし） | 時刻ありの予定。60分として登録し、備考に「終了時刻は仮」と書く |
| 「10/15 までに資料をご提出ください」 | 終日の予定（10/15 の1日） |
| 「10/20〜10/31 申告書作成」 | 終日の予定（10/20〜10/31 の期間） |
| 「来週金曜」「2週間後」 | メッセージの送信日を基準に日付に直し、計画表に元の書き方も書く |
| 「11月中旬」「年明け」「資料受領後1週間」 | 日付が決まらないので登録しない。計画表で「要確認」にする |

- 年が書かれていない日付は、送信日以降で最も近い日付とする（12月に送った「1/15」は翌年）。
- 日付に曜日が添えてあれば、曜日が合っているか確かめる。合わなければ「要確認」。
- 海外のクライアントで時刻のタイムゾーンが日本時間でない場合（「NY time」「PST」等）は、日本時間に直して登録し、
  備考に元の時刻を書く。
- 「お客様の作業」（資料提出など）も「こちらの作業」（申告書作成など）も登録してよい。こちら宛の内部メモ
  （「念のため前日にリマインド」等）はユーザーが望めば登録する。

### 3. 予定のタイトル・メモ・設定を決める

- **タイトル:** `【<クライアント名>】<内容>`（例: `【Jason Hahn】資料提出期限`、`【Aliatta】決算レビュー面談`）。
  200 文字以内。クライアント名は Dropbox のクライアントフォルダ名（`gmail-attachment-to-dropbox` スキルの
  `references/client-map.md` 参照）に合わせると、後で探しやすい。
- **メモ（notes）:** 出典と原文を入れる。5000 文字以内。
  ```
  出典: Gmail 2026-10-01 送信「Tax return schedule」 / Slack #client-aliatta 2026-10-01
  原文: 10/15 までに W-2 と 1099 をご提出ください
  ```
  場所（来社・Zoom・先方オフィス）や Zoom の URL が分かればメモに書く。
- **時刻ありの予定:** `transparency: "OPAQUE"`（その時間を埋める。Wix Bookings の予約枠もその時間はふさがる）。
- **終日の予定（期限・期間）:** `allDay: true`、`transparency: "TRANSPARENT"`
  （その日の予約枠をふさがない。期限は作業時間ではないため）。
  `end.localDate` は **最終日の翌日の 00:00:00**（Wix の仕様。最終日を含まない）。

### 4. 重複を確認する

登録する期間について、登録先スケジュールの既存の予定を検索する（`references/config.md` の Query Events）。

```json
{
  "fromLocalDate": "<最初の予定の日>T00:00:00",
  "toLocalDate": "<最後の予定の日>T23:59:59",
  "query": { "cursorPaging": { "limit": 100 } },
  "fields": ["PI_FIELDS"]
}
```

`scheduleId` で絞り込まない。予約（来社相談・Dinner Meeting など）はサービスごとのスケジュールに入っていて、
山本真美子のスケジュール ID で絞ると出てこない（予約側では `resources[].scheduleId` に山本真美子が入る）。
`PI_FIELDS` を付けないとタイトルが返らない。`pagingMetadata.hasNext` が true なら続きも読む。
同じ日に同じクライアント名を含むタイトルの予定があれば、計画表で「登録済みの可能性」として示す。
なお、ダッシュボードで斜線付きで表示される「ブロック時間」（研修会・懇親会など）はこの API では返ってこない。

### 5. 計画を提示して確認を取る（必須）

登録の前に必ず次の形で提示し、了承を得る。了承なしに登録しない。

```
| # | 日時 | タイトル | 種類 | 出典 | 備考 |
|---|---|---|---|---|---|
| 1 | 10/15（水） 終日 | 【Jason Hahn】資料提出期限（W-2・1099） | 終日・予約枠はふさがない | Gmail 10/1「Tax return schedule」 | |
| 2 | 11/1（土） 14:00–15:00 | 【Jason Hahn】申告書レビュー面談（Zoom） | 時刻あり・予約枠をふさぐ | 同上 | |
| 3 | 11/5（水） 10:00–11:00 | 【Jason Hahn】最終確認 | 時刻あり | 同上 | 終了時刻は仮（60分） |
| 4 | — | 【Jason Hahn】電子申告 | 登録しない | 同上 | 「11月中旬」で日付が未定。要確認 |
```

ユーザーが修正を指示したら表を直して再提示する。

### 6. Wix に登録する

了承された予定ごとに Create Event を呼ぶ（`CallWixSiteAPI`、`siteId` は config の値）。

時刻ありの予定:

```json
{
  "event": {
    "scheduleId": "<config の scheduleId>",
    "title": "【Jason Hahn】申告書レビュー面談（Zoom）",
    "start": { "localDate": "2026-11-01T14:00:00" },
    "end": { "localDate": "2026-11-01T15:00:00" },
    "timeZone": "Asia/Tokyo",
    "transparency": "OPAQUE",
    "notes": "出典: …\n原文: …"
  }
}
```

終日の予定（10/20〜10/31 の場合）:

```json
{
  "event": {
    "scheduleId": "<config の scheduleId>",
    "title": "【Jason Hahn】申告書作成",
    "start": { "localDate": "2026-10-20T00:00:00" },
    "end": { "localDate": "2026-11-01T00:00:00" },
    "timeZone": "Asia/Tokyo",
    "allDay": true,
    "transparency": "TRANSPARENT",
    "notes": "出典: …\n原文: …"
  }
}
```

- `recurrenceRule` は付けない（繰り返しにしない）。
- 返ってきた `event.id` を控える。エラーが出た予定は飛ばさずに止め、エラー内容をユーザーに伝える。
- config の「動作確認」が `未検証` の場合は、最初の1件だけ登録して、Wix ダッシュボードの予約カレンダー
  （山本真美子）に表示されているかをユーザーに確かめてもらってから残りを登録する。
  確認できたら config.md の `未検証` を `確認済み（日付）` に書き換える。

### 7. 結果を報告する

- 登録した予定を「日時・タイトル・event ID」の一覧で示す。
- 登録しなかった予定（要確認・登録済み・ユーザーが外したもの）を分けて示す。
- 時刻ありの予定のうち **来社**（六本木ヒルズ森タワーでの面談）があれば、`qr-code-request` スキルで
  入館 QR コード発行依頼の下書きを作るか確認する。

## 日程が変わったとき

クライアントに日程変更を連絡した場合は、手順4と同じ検索で既存の予定（タイトルの `【クライアント名】` で判断）を探し、
「変更前 → 変更後」の表を示して了承を得てから、Update Event（日時の変更）または Cancel Event（取りやめ）を使う。
これらの API は `references/config.md` の注意どおり、ドキュメントで形を確かめてから呼ぶ。
古い予定を消さずに新しい予定を足すと二重になるので、必ず既存の予定を先に探す。
